# Ecosystems: what the harness detects, and what you derive from it

Preflight prints one line per manifest it finds:

```
ecosystem=<name> manifest=<relpath> root=<yes|no> lockfile=<yes|no> deps_present=<yes|no|n/a>
```

From those lines and this file you derive, per run: what needs the network
(bootstrap, done by you), what the worker runs offline, the gate commands, the
generated files and who regenerates them, the warm directories to preserve, the
environment a worker must never change, and how to repair a lockfile conflict.
**The repository's own CI configuration always wins** over the conventional
defaults below; read it in Phase 1.

Two sections are **measured** (Rust and Node, from real orchestrated runs). The
others are **conventional defaults, unmeasured** — verify against the repo
before trusting a command.

## Detection

| manifest | ecosystem | lockfile | dependency store (beside the manifest) |
| --- | --- | --- | --- |
| `package.json` | node | `package-lock.json`, `pnpm-lock.yaml`, `yarn.lock` | `node_modules/` |
| `Cargo.toml` | rust | `Cargo.lock` | `target/` (workspace root only) |
| `pyproject.toml` | python | `uv.lock`, `poetry.lock`, `requirements*.txt` | `.venv/` |
| `go.mod` | go | `go.sum` | global (`GOMODCACHE`, `GOCACHE`) |
| `pom.xml` | maven | none by default | global (`~/.m2/repository`); `target/` per module |
| `build.gradle`, `build.gradle.kts` | gradle | `gradle.lockfile` if locking is on | global (`~/.gradle/caches`); `build/`, `.gradle/` per project |
| `*.sln`, `*.csproj` | dotnet | `packages.lock.json` if lock mode is on | global (`~/.nuget/packages`); `bin/`, `obj/` per project |

`root=yes` marks the root-most manifest per ecosystem; that is the one `reset`
reports warm state for. `deps_present` is a heuristic (the store directory
exists), not proof the store matches the lockfile.

## The bootstrap procedure, for any ecosystem

Workers have no network unless `references/sandbox.md` records a measured
exception. So anything that resolves or downloads happens outside the sandbox,
by you, in this order:

1. On the invoke branch: edit the manifest, run the ecosystem's install so the
   lockfile is regenerated by the tool (never by hand), and commit **only the
   manifest and lockfile**. The store is git-ignored and does not travel.
   This commit advances `base_sha`.
2. `reset` every slot to the new base.
3. In each slot, unsandboxed, run the install once so the store matches the
   lockfile. Re-run whenever `git diff --name-only <old-base>..<new-base> --
   <lockfile>` is non-empty.
4. Launch. The worker's brief says the store is present and that it must not
   run an install.

That is the whole bootstrap exception. Types, schemas, migrations, interfaces
and wiring are not bootstrap; they are a foundation workstream.

## Worker-rules lines, per ecosystem

Inline the lines for every detected ecosystem into the brief's **Worker rules**.

- **node** — "There is no network. `node_modules` is installed for you; do not
  run `npm install`, `npm ci`, `pnpm install` or `yarn`. `npx <bin>` works only
  for binaries already in `node_modules/.bin`."
- **rust** — "There is no network. Every `cargo` call passes `--offline` after
  the subcommand (`cargo test -p x --offline`). `Blocking waiting for file lock
  on package cache` is normal when workers run concurrently; wait. Never pass
  `--ignored`."
- **python** — "There is no network. The virtual environment is installed for
  you; use `uv run ...` (or the interpreter inside `.venv`). Do not run
  `uv sync`, `pip install` or `poetry install`."
- **go** — "There is no network. `GOFLAGS=-mod=mod GOPROXY=off` is set so a
  missing module fails fast instead of hanging. Do not run `go get` or `go mod
  tidy`."
- **maven** — "There is no network. Pass `-o` to every `mvn` call. A missing
  artifact is a blocker, not something to retry."
- **gradle** — "There is no network. Pass `--offline` to every Gradle call."
- **dotnet** — "There is no network. Pass `--no-restore` to `dotnet build` and
  `dotnet test`; the restore has been done for you."

Every ecosystem: "You cannot add a dependency. If you need one, stop and report
it as a blocker with kind `needs_dependency`." And: "Do not run tests the
repository excludes from its default gate."

## node (measured)

- **Bootstrap (network):** `npm ci` (or `pnpm install --frozen-lockfile`,
  `yarn install --immutable`) in each slot, and after any lockfile change.
  Adding a dependency edits `package.json` plus the lockfile — yours.
- **Offline:** workers never install. Scripts (`npm run ...`) and local binaries
  (`npx tsc`, `npx vite build`) work offline; `npx` of an uninstalled package
  tries to fetch and fails.
- **Gates (conventional):** `npx tsc --noEmit`, `npx eslint .`, `npm test` or
  `npx vitest run`, `npx vite build`. The `scripts` block in `package.json` and
  the CI workflow name the real ones.
- **Generated files:** the lockfile (never hand-merged); codegen outputs such as
  API-client or type files, regenerated by the worker that owns their source of
  truth, using the repo's own script, offline.
- **Warm state:** `node_modules/` beside each `package.json` (a workspace root
  hoists into one). `dist/` when another build embeds it (see Tauri, below).
- **Env a worker must not change:** `NODE_ENV` for a build (it changes the
  bundle), any `npm_config_*` that relocates the store or cache.
- **Parallelism:** bundlers use threads internally; no per-worker job flag.
  Weight about 2 GB per concurrent build.
- **Lockfile conflict:** take the base version, then after all merges run
  `npm install --package-lock-only` once, yourself (network in general). Never
  resolve the JSON by hand.

## rust (measured)

- **Bootstrap (network):** a new dependency is a `Cargo.toml` edit plus `cargo
  fetch`, committed with the resulting `Cargo.lock` — yours, on the invoke
  branch. Then one `cargo build` per slot to warm `target/`.
- **Offline:** `--offline` on every cargo call; also set `CARGO_NET_OFFLINE=true`
  in the spec's `env`.
- **Gates (conventional):** `cargo fmt --all --check`; `cargo clippy --workspace
  --all-targets -- -D warnings`; `cargo test`; `cargo build`. Scope a worker's
  Verification with `-p <crate>`; you run the workspace after merge.
- **Generated files:** `Cargo.lock`; bindings generated from Rust types (ts-rs,
  specta, uniffi) — the owning worker regenerates with the repo's generator.
- **Warm state:** `target/` beside the workspace `Cargo.toml`, several GB per
  slot (5.5 GB measured for a desktop app). `reset` preserves it because it
  uses `git clean -fd`, never `-x`.
- **Env a worker must not change:** `CARGO_TARGET_DIR`, `RUSTFLAGS`,
  `CARGO_PROFILE_*`, `CARGO_INCREMENTAL`, `RUSTC_WRAPPER` — each alters the
  fingerprint and forces the full rebuild the warm pool exists to avoid. Safe:
  `CARGO_NET_OFFLINE`, `CARGO_TERM_COLOR=never`, `CARGO_BUILD_JOBS`.
- **Parallelism:** `CARGO_BUILD_JOBS = floor(cpus / workers)`; preflight prints
  the table. Weight about 6 GB per concurrent build (rustc plus linker).
- **Lockfile conflict:** take the base `Cargo.lock`, then after all merges run
  `cargo metadata --offline` once — it adds missing entries without
  re-resolving. Never `cargo generate-lockfile` or `cargo update`; both
  re-resolve, bump unrelated versions, and want the network.
- **Concurrency:** `Blocking waiting for file lock on package cache` and `on
  build directory` are normal; workers wait.
- **Tests marked `#[ignore]`:** excluded from the gate for a reason (network,
  hardware, minutes of runtime). Nobody passes `--ignored`.

### Tauri (rust + node in one tree)

The Rust crate embeds the frontend's `dist/` (`frontendDist` in
`tauri.conf.json`) and cannot compile until it exists. Seed each slot yourself:
`npm ci` then the frontend build, then `cargo build --offline`. A Rust worker
must not rebuild `dist/`; a frontend worker that owns it may. Deep `target/`
paths are why `core.longpaths` matters. A Defender exclusion on the pool root
roughly halved build times (measured once; re-measure on your machine).

## python (conventional, unmeasured)

- **Bootstrap (network):** `uv sync` (or `poetry install`, `pip install -e
  .[dev]`) per slot and after any lockfile change. Adding a package edits
  `pyproject.toml` plus the lockfile — yours.
- **Offline:** with `.venv/` present, `uv run ...` needs nothing. Belt and
  braces: `UV_OFFLINE=1`, `PIP_NO_INDEX=1`.
- **Gates (conventional):** `ruff check .`, `ruff format --check .`, `mypy` or
  `pyright`, `pytest`.
- **Generated files:** the lockfile; exported OpenAPI documents and clients.
  Alembic or Django migrations are hand-written source — feature work, not
  bootstrap, not generated.
- **Warm state:** `.venv/` beside `pyproject.toml`; tool caches are cheap.
- **Env a worker must not change:** `VIRTUAL_ENV`, `UV_PROJECT_ENVIRONMENT`,
  `PYTHONPATH`.
- **Parallelism:** `pytest -n <k>` only if the repo already uses xdist. Weight
  about 1 GB.
- **Lockfile conflict:** take the base, then `uv lock` (or `poetry lock
  --no-update`) once after merging — yours, network likely.

## go (conventional, unmeasured)

- **Bootstrap (network):** `go mod download` once; the module cache is global
  and shared by every slot. Adding a module edits `go.mod`/`go.sum` — yours.
- **Offline:** `GOFLAGS=-mod=mod`, `GOPROXY=off` in the spec's `env`.
- **Gates (conventional):** `gofmt -l .`, `go vet ./...`, `go build ./...`,
  `go test ./...`, `golangci-lint run` if configured.
- **Generated files:** `go.sum`; `go generate` outputs, regenerated by the
  worker that owns the source.
- **Warm state:** global `GOCACHE`; nothing per slot to preserve.
- **Env a worker must not change:** `GOCACHE`, `GOMODCACHE`, `CGO_ENABLED`.
- **Parallelism:** `go build -p <n>` or `GOMAXPROCS`. Weight about 1 GB.
- **Lockfile conflict:** `go.sum` — take the base, `go mod tidy` after merge,
  yours.

## maven (conventional, unmeasured)

- **Bootstrap (network):** `mvn -B dependency:go-offline` or a first `mvn -B
  verify`; populates the global `~/.m2/repository`.
- **Offline:** `mvn -o`. A missing artifact fails fast.
- **Gates:** `mvn -B -o verify`; scope with `-pl <module> -am`.
- **Generated files:** `target/` per module, not committed.
- **Warm state:** `target/` per module (cheap); the real warm state is global.
- **Env a worker must not change:** `maven.repo.local`, `MAVEN_OPTS` heap.
- **Parallelism:** `mvn -T <n>`. Weight about 3 GB (JVM).
- **Conflicts:** no lockfile; a POM version conflict is a source conflict you
  resolve by hand.

## gradle (conventional, unmeasured)

- **Bootstrap (network):** first `gradlew build`; the wrapper may also download
  a Gradle distribution. Global `~/.gradle/caches`.
- **Offline:** `--offline` on every call.
- **Gates:** `gradlew check` (or `build`, `test`, `spotlessCheck`).
- **Generated files:** `build/` per project; `gradle.lockfile` when locking is
  enabled (take base, `--write-locks` after merge, yours).
- **Warm state:** `build/`, `.gradle/` per project; global caches.
- **Env a worker must not change:** `GRADLE_USER_HOME`, `GRADLE_OPTS`.
- **Parallelism:** `org.gradle.workers.max=<n>`. Weight about 3 GB.

## dotnet (conventional, unmeasured)

- **Bootstrap (network):** `dotnet restore` per slot; it writes
  `obj/project.assets.json` per project as well as the global NuGet cache, so
  repeat it after any `reset` to a base whose package references changed.
- **Offline:** `dotnet build --no-restore`, `dotnet test --no-restore`.
- **Gates:** `dotnet format --verify-no-changes`, `dotnet build -warnaserror`,
  `dotnet test`.
- **Generated files:** `packages.lock.json` when lock mode is on (take base,
  `dotnet restore --force-evaluate` after merge, yours); `obj/` assets.
- **Warm state:** `bin/`, `obj/` per project.
- **Env a worker must not change:** `NUGET_PACKAGES`.
- **Parallelism:** MSBuild `-m:<n>`. Weight about 2 GB.
